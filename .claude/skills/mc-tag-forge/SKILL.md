# Minecraft 标签锻造台

单文件 HTML 工具（`mc-tag-forge.html`，无后端无依赖）。仓库另含 `tests/`（零依赖 node 测试，含四张真实截图语料）和 `index.html`（GitHub Pages 入口，只做跳转不复制内容）。
公开托管在 GitHub Pages，**给别人也能用**，所以改动要考虑非 HoloCraft 玩家（跨服注意事项写在 README）。两个模式：
**创作** = 段落 / 花体 / 符号 / 包裹 / 渐变 / 输出；**逆推** = 截图 → 逐字取色 → 拟合色标 → 生成代码。
目标服务器：HoloCraft，语法为 EssentialsX 渐变标签。

**已知限制（不是 bug，别重新诊断）**：逆推的自动拟合不验证"这段像不像渐变文字"，喂任何截图（背包 GUI、随机照片）都会硬拟合出一条曲线，分数可能还很高（因为选区里的像素本来就很接近同一色，比如物品数量的白色数字）。这是设计上的取舍，不是识别失败——工具只对"一行渐变色文字"的选区有意义。对付不适用的图，用「取色笔」（在图上点一下直接读像素颜色，写进「我的配色」当前选中的色标），不用等自动拟合。

**双语**：页头有中/EN 切换按钮（`S.lang`），详见 `references/architecture.md` 第 9 节。改任何用户可见文案（按钮、提示、toast）时，**两种语言一起改**，不要只改中文——用 `t(zh,en)` 就地写，别漏掉 en 参数。

## 每次开工前

1. **不要重新验证下面那张表里的事实。** 每一条都是花了多轮游戏内实测换来的，重推等于浪费 token 和用户的时间。
2. **改代码前先读 `references/architecture.md`**，不要通读整个 HTML 去摸索结构。
3. 长度、色值、字符数**一律用代码算**，不手算。已经因为手算错过两次。
4. **改完必须跑 `node tests/run-all.js`**，全绿才交付。这套测试抓到过 PRGME 映射错字、hover 污染输出、包裹成本算错、逆推把 tooltip 边框当字符——全部是看代码看不出来的。
5. **只有交付 `mc-tag-forge.html` 时**，回复最后一行写「这是第 N 次 update」，N 取下面的计数器加一，并同步更新本文件里的计数器。交付 skill 文档或其他文件**不计数、不写这一行**。
6. **没改动的文件不要重新交付。** 一次回复里只放这轮真正变过的文件。

## 已验证的平台事实

| 事实 | 实测依据 |
|---|---|
| anvil 改名上限 **50**，数的是 **UTF-16 单元** | `{#f00>}`+20 个 🅐 类字符+`{#00f<}` 在第 50 个 UTF-16 单元处被截断（码点算只有 34） |
| emoji / 增补平面字符 = **2 格**；BMP 字符 = 1 格 | 同上 |
| 标签成本：`{#rrggbb>}`=10、`{#rgb>}`=**7**、`{#&9>}`=6 | 数字符 |
| 三位简写按 **CSS 逐位翻倍**展开（`b`→`bb`） | `{#bdf>}` 实测渲染 #BBDDFF |
| 渐变标签里可以塞传统色码 `{#&9>}`，但只有 16 色 | `{#&9>}`=#5555FF、`{#&d<}`=#FF55FF |
| **四色及以上可用**，一串里能有多个 `{#x<>}` | `{#f00>}RRRR{#0f0<>}GGGG{#00f<>}BBBB{#ff0<}` 三段过渡全部正常 |
| 渐变 = **逐字线性 RGB 插值**，每段独立跑满全程 | 多张截图逐字取色与算法输出逐字节一致 |
| 颜色代码会**重置格式**，所以每段都要重新发 `&l` 之类 | — |
| MC **不做组合符定位**：`a`+U+0308 会往右飘一格，且占 2 格 | 与网站输出对比放大确认 |
| 预组合字符（ä ö ẗ ṡ ã á）**1 格且贴合** | 游戏内实测 `Täködächï` |
| 34 种花体在 HoloCraft **全部能渲染，零方框** | 成书探针，34 行 |
| 但 8 种在游戏里辨识度为零：`衬线粗体/黑板粗体/无衬线/无衬线粗/等宽` 塌成普通字，`衬线斜体/衬线粗斜/无衬线斜` 塌成斜体 | 8×16 点阵放不下字重与衬线差别 |
| `/emoji` 短代码（`:star:`）**只在聊天生效**；物品名要用字符本体 | 🐙 在 anvil 直接可用，且不在 `/emoji` 列表里 |
| 每多一段约 **+14 格**（各自要开一对渐变标签） | 数字符 |
| 包裹只花字符本身的钱（已并进首尾段，不另开标签） | 改之前一对 `「」` 要 30 格，现在 2 格 |
| 像素符号大部分是**原版 Unifont 自带**，不是服务器资源包做的 | 1791 个候选码位（穷举 7 个标准 emoji 区块）实测贴进 anvil 成书，绝大多数都渲染出了黑白线条符号，不是 🐙 那种彩色画风——黑白线条正是 Unifont 的典型特征。少数几个渲染失败的显示成「方块里写着十六进制码点」（比如 `1FAC8`/`1FACD`/`1FAEA`），集中在最新的 P3 区块（Symbols and Pictographs Extended-A，Unicode 2022 年之后才加的那批），大概率是版本太新、Unifont 还没收录，不是资源包的锅。**方块里带十六进制码点文字 = MC 自己的"完全没有这个字形"兜底显示，用这个特征区分"渲染失败"和"渲染成简单黑白符号"（后者算成功）** |
